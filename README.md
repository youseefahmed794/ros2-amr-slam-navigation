# AMR LiDAR SLAM and Navigation

Research simulation prototype using ROS 2 Jazzy, Gazebo Harmonic,
SLAM Toolbox and Nav2. The configured planner is Smac Hybrid-A*;
the controller is Regulated Pure Pursuit.

## Simulation model

Spawn position is (1.5, 0), avoiding the pillar at the origin.
The base-link inertial origin is shifted 0.05 m rearward for static support.
This mass-distribution assumption requires physical-hardware calibration.

Wheel-center geometry remains 0.40 m. DiffDrive effective track is
0.350006373769 m, empirically calibrated for this Gazebo configuration.
Separate unseen-speed tests supported it for in-place turns.
It is not a hardware wheel-spacing measurement.

The supplied map is an analytic raster generated by
`scripts/generate_default_map.py`, not a SLAM survey.

## Build and launch

Install package.xml dependencies, including Nav2, SLAM Toolbox and ros_gz.
In a ROS 2 Jazzy environment, build and test:

    colcon build --symlink-install
    source install/setup.bash
    colcon test --event-handlers console_direct+
    colcon test-result --verbose

Mapping:

    ros2 launch amr_slam_navigation slam_gazebo.launch.py gui:=false rviz:=true

Navigation:

    ros2 launch amr_slam_navigation navigation.launch.py gui:=false rviz:=true

Recorded runs requested NVIDIA PRIME render offload with
`__NV_PRIME_RENDER_OFFLOAD=1` and `__GLX_VENDOR_LIBRARY_NAME=nvidia`.
GPU use was observed with nvidia-smi.

## Validation scope

These are three distinct single-run smoke cases, not a repeated
success-rate benchmark. Obstacle avoidance, recovery, map accuracy,
terrain/payload robustness and hardware transfer remain unvalidated.

`dynamic_obstacle_node` publishes synthetic TF and Odometry diagnostics.
It does not spawn Gazebo collision bodies or feed Nav2 obstacle observations.

The JSON records preserve completed local runs. A portable automated
runtime reproduction suite remains to be packaged.
